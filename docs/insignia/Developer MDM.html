The Future MDM/Identity Kernel: Best-of-Industry + RealMDM Doctrine

This SPA is a self-contained execution blueprint for an 8-person, AI-augmented engineering team building a billion-scale identity, master data, evidence, relationship, policy-context and projection platform. It compares the RealMDM approach against conventional MDM, modern data fabric/mesh, entity resolution, knowledge graph, data contract, governance and authorization trends, then converts the best combined strategy into developer-level architecture, schemas, services, APIs, workflows, test gates and rollout plans.

What this document assumes

Consent management and ABAC are not rebuilt here. The design assumes an external Consent Management Platform (CMP) and an OPA-based ABAC shell. RealMDM becomes the identity, relationship, evidence, policy-context, projection, provenance and data-contract kernel that feeds those systems and enforces their decisions at runtime.

Implementation thesis: do not build a generic MDM hub. Build a pure identity + relationship contract kernel, use event-sourced portals for state changes, keep sensitive data behind SAS, project domain-specific read models, and let AI propose changes only through calibrated, audited, reversible workflows.

01 · Comparative MDM Approach: Us vs Them

The strongest industry patterns are not wrong. Traditional MDM, data fabric, data mesh, CDPs, identity graphs, knowledge graphs, semantic layers, policy engines, lakehouse governance and data contracts each solve a part of the problem. The weakness is that each usually optimizes one plane while leaving identity, context, evidence, consent, policy, history or operational workflow under-modeled.

02 · Best-of-Both Strategy

The best strategy is not “replace the market with doctrine.” It is to use the doctrine to decide which market pattern belongs in which layer.

Keep

Conventional MDM discipline

Data quality, stewardship queues, survivorship rules, dedupe metrics, lineage, manual review and governed release gates remain essential.

Upgrade

Entity resolution

Move from static matching to deterministic + probabilistic + graph + calibrated AI + human adjudication. Store candidate links before verified truth.

Reject

Universal business schema

Do not force HR, clinical, CRM, education and finance to share one overloaded “person” or “account” shape.

Adopt

Data contracts

Every domain pack ships schemas, quality assertions, event contracts, privacy tags and policy expectations.

Adopt

Open lineage and provenance

Every event, projection, model decision and portal run emits lineage metadata and can be replayed or audited.

Constrain

Graph and AI

Use graph and AI for reasoning, candidate generation and explanation. Keep the authoritative write path deterministic.

03 · Optimizations and Changes to Add to RealMDM

The research compendium suggests several refinements to the existing RealMDM doctrine. These improve buildability, interoperability, auditability, cost control and developer clarity.

1. Add a Contract Registry

Every domain pack must publish schemas, event formats, quality tests, privacy tags, projection definitions and portal requirements. Use JSON Schema/Protobuf for data and SHACL-like constraints for graph semantics.

2. Make graph a projection, not the only truth

At billion scale, the graph is a reasoning/index plane. The authoritative write truth is the event log plus transactional contract store. Rebuild graph projections from log.

3. Add Policy Context Builder

OPA/ABAC engineers should not query 12 systems. RealMDM builds subject-resource-purpose-context documents and gives OPA a clean decision input.

4. Add Consent Adapter only

Do not rebuild consent. Store external consent decision references, cached signed decisions, validity windows and purpose/data-category bindings.

5. Add Evidence/Claim taxonomy

Every claim must point to evidence or provenance. Claim is not truth until verified by portal or steward. Evidence can expire, be revoked, or be jurisdiction-specific.

6. Add Model Calibration Registry

Entity resolution models must have model version, ECE, test corpus, drift thresholds, decision logs and automatic downgrade-to-human when calibration fails.

7. Add deterministic cache rules

Semantic caching is useful for documentation and non-sensitive reasoning, but forbidden for PII/PHI/PCI reveal. Sensitive caches must be key-scoped, tenant-scoped and token-versioned.

8. Add Migration Adapters

Provide ready adapters for Supabase/Postgres, Salesforce, Workday, Snowflake, FHIR/HL7, CSV/SFTP and Kafka CDC. Migration is product, not consulting only.

Refined doctrine: RealMDM is not “the one database.” It is the control plane of identity, evidence, relationship contracts, provenance, policy context and governed projections. Transactional apps keep domain transactions; RealMDM owns the meaning that lets those transactions be safely interpreted.

04 · Clear-Cut Target Architecture

This architecture is optimized for Go core services, Kafka-compatible streaming, Temporal durable workflows, external CMP, OPA ABAC shell, graph reasoning, MLOps and cloud-native operations.

Governance Plane

Services: Command Gateway, Portal Service, Policy Context Builder, OPA Adapter, Consent Adapter, Domain Pack Registry. Purpose: only governed portals can mutate reality.

Secure Data Plane

Services: Sensitive Access Service, Token Vault, KMS/HSM integration, Key Cache/CMM, Revocation Broadcaster. Purpose: sensitive data is tokenized, revealed only under policy, and crypto-shreddable.

Reality Plane

Services: Identity Resolver, Relationship Contract Service, Event Log, Projection Consumers, Graph Projector, Audit Store, Temporal workflows. Purpose: immutable truth history, contract state, and domain projections.

CREATE TABLE universal_entity (
  entity_id             UUID PRIMARY KEY,
  entity_type           entity_type NOT NULL,
  home_region           TEXT NOT NULL,

  display_label_token   TEXT NULL,              -- optional encrypted/vaulted display label token

CREATE TABLE identity_handle (
  handle_id             UUID PRIMARY KEY,
  handle_type           TEXT NOT NULL,           -- EMAIL, PHONE, GOV_ID, MRN, EMPLOYEE_ID, DEVICE_UUID, EXTERNAL_ID

func (s *ResolverService) Resolve(ctx context.Context, req *pb.ResolveRequest) (*pb.ResolveResponse, error) {
    // 1. Policy shell: every resolution attempt must have a purpose and tenant.
    decision, err := s.policy.Check(ctx, PolicyInput{
        Actor: req.RequestedBy,
        Action: "identity.resolve",
        Purpose: req.Purpose,
        TenantID: req.TenantId,
        Resource: "universal_entity",
    })
    if err != nil || !decision.Allow {
        return &pb.ResolveResponse{ResolutionStatus: "DENIED"}, nil
    }

    // 2. Deterministic pass: only high-grade handles participate in auto-link.
    hits := s.handleIndex.LookupExact(ctx, req.TenantId, req.Handles)
    if hits.HasSingleHighAssuranceEntity() {
        return s.linkOrReturn(ctx, req, hits.EntityID(), "DETERMINISTIC", 0.999)
    }

    // 3. Candidate generation: fuzzy + graph + vector features, never final authority.
    candidates := s.candidateGenerator.Generate(ctx, req)
    features := s.featureBuilder.Build(req, candidates)

    // 4. Calibrated model score: never trust raw model logits.
    scored := s.model.Score(ctx, features)
    calibrated := s.calibrator.Apply(scored)

    // 5. Risk routing: PHI/PII/legal identity has stricter thresholds.
    risk := s.riskScorer.Score(req, candidates, calibrated)
    if calibrated.TopScore > 0.985 && risk.Level == "LOW" && calibrated.ECE <= 0.05 {
        return s.linkOrReturn(ctx, req, calibrated.TopEntityID, "CALIBRATED_AI_LOW_RISK", calibrated.TopScore)
    }

    // 6. Ambiguity goes to suggestion plane, not master tables.
    suggestionID := s.steward.CreateSuggestion(ctx, StewardSuggestion{
        Type: "LINK_CANDIDATE",
        Candidates: candidates,
        Score: calibrated.TopScore,
        Risk: risk,
        Evidence: features.EvidenceRefs,
        Explanation: calibrated.Explanation,
    })
    return &pb.ResolveResponse{
        ResolutionStatus: "AMBIGUOUS",
        Confidence: calibrated.TopScore,
        CandidateEntityIds: candidates.IDs(),
        StewardCaseId: suggestionID,
    }, nil
}

func CandidateToEmployeeWorkflow(ctx workflow.Context, input CandidateToEmployeeInput) error {

    var offer ArtifactRef

    })

        return nil
    }

    // Step 3: Consent + ABAC shell. Consent is external CMP; OPA is external PDP shell.
    policyResult, err := activities.CheckPolicy(ctx, PolicyCheck{

        Action: "relationship.verify",
        Purpose: "EMPLOYMENT_ONBOARDING",
        TenantID: input.TenantID,
        Subject: entityID,
        EvidenceRefs: state.EvidenceRefs,
    })
    if err != nil || !policyResult.Allow { return errors.New("policy denied") }

    // Step 4: Idempotent contract write.
    contractID, err := activities.VerifyRelationshipContract(ctx, VerifyContract{
        SubjectEntityID: entityID,
        ObjectEntityID: input.EmployerOrgID,
        RelationshipType: "EMPLOYED_BY",
        Domain: "HR",
        AppID: input.AppID,
        TenantID: input.TenantID,
        EvidenceRefs: state.EvidenceRefs,
        PolicyDecisionID: policyResult.DecisionID,
        IdempotencyKey: input.IdempotencyKey + ":verify-contract",
    })
    if err != nil { return err }

    // Step 5: Emit event and wait for projection confirmation when RYOW is required.
    activities.EmitEvent(ctx, "realmdm.relationship.contract.verified.v1", contractID)
    activities.NotifyCommandCompleted(ctx, input.CorrelationID)

    // Step 6: Continue-as-new before history gets large.
    if workflow.GetInfo(ctx).GetCurrentHistoryLength() > 10000 {
        drainSignals(ctx, &state) // atomic signal draining before reincarnation
        return workflow.NewContinueAsNewError(ctx, CandidateToEmployeeWorkflow, state.ToInput())
    }
    return nil
}

Candidate generation

Deterministic exact handles first. Then fuzzy string similarity, address/geohash matching, graph neighborhood, vector evidence search.

Calibrated scoring

Digital Jury

For PHI/PII/legal identity merges, require agreement between deterministic rules, graph model and LLM judge or escalate to human.

All AI outputs write to steward_suggestion with evidence, explanation, risk, model version and replayable input hash.

Use GraphRAG to answer why and what-if questions, not to mutate truth. Retrieve k-hop subgraphs and evidence, synthesize explanation.

11 · Billions-Scale Design

At billion-scale, correctness and partitioning matter more than a single database choice. The architecture must tolerate multi-region partitioning, high write volume, graph projection lag, key revocation, model drift and domain isolation.

Partitioning strategy

LayerPartition keyWhyCross-partition approach
Event topicsregion + tenant_id + entity_id hashKeeps entity event order and tenant isolation.Global identity links use async reconciliation events.
Kernel DBtenant_id/app_id + entity_id hashPredictable hot-spot control.Cross-tenant edges require explicit governance portal.
Token vaulttenant_id + key shardLimits breach blast radius.Never do global token lookups without tenant scope.
Graph projectiontenant/domain subgraph + global sparse identity graphMost graph queries are local; global graph remains sparse.Federated graph query for authorized global investigations.
Vector indexdomain + sensitivity + tenantAvoid semantic bleed across tenants or privacy contexts.Only compare across scopes via portal-authorized job.

Scale constraints

Write path

Append events, idempotent contract writes, outbox/CDC, partition-aware producer keys.

Read path

Use operational cache, graph projection, search projection and domain views. Never query full event history on user request.

Crypto path

Caching CMM reduces KMS load; revocation signal overrides TTL; fail-closed on KMS miss/down for empty cache.

AI path

Batch inference for candidate recall; online inference only for narrow, bounded requests; no AI in critical synchronous path unless cached/deterministic.

Migration SQL sketch

sql
-- From a naive Supabase-style table to RealMDM shadow registry
-- Original anti-pattern:
-- person(id, name, email, phone, employee_id, org_id, salary, address, status)

-- Step 1: Keep app table intact. Add crosswalk and RealMDM IDs.
ALTER TABLE app_person ADD COLUMN realmdm_entity_id UUID NULL;
ALTER TABLE app_employee ADD COLUMN realmdm_contract_id UUID NULL;

-- Step 2: Backfill handles into RealMDM via ingestion job, not direct SQL writes.
-- For each row: tokenize email/phone, hash normalized values, call IdentityResolver.Resolve.

-- Step 3: Replace application joins with RealMDM crosswalk joins.
CREATE VIEW app_employee_resolved AS
SELECT e.*, p.realmdm_entity_id, e.realmdm_contract_id
FROM app_employee e
JOIN app_person p ON p.id = e.person_id;

-- Step 4: Portalize new writes.
-- Disable direct creation of employee status after cutover.
CREATE OR REPLACE FUNCTION prevent_direct_employee_activation()
RETURNS trigger AS $$
BEGIN
  IF NEW.status = 'ACTIVE' AND NEW.realmdm_contract_id IS NULL THEN
    RAISE EXCEPTION 'Use RealMDM candidate_to_employee portal';
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

Migration policy

  • Do not delete old IDs. Preserve source IDs as crosswalks forever unless legally required to shred sensitive data.
  • Do not mass-merge. Produce candidate links first; verify only high-confidence deterministic cases.
  • Do not block application traffic. Use shadow mode until projections are proven.
  • Portalize new writes before cleaning all history. Stop new pollution while AI/humans clean old data.
  • Keep rollback. Source systems continue operating until RealMDM gates pass.

16 · Counterarguments, Criticism and Resolution

CriticismWhy it is partly rightResolution in this blueprint
“This is too complex.”It is more complex than a CRUD table.The complexity already exists in identity, privacy, policy and context. This design makes it explicit, testable and owned.
“Graph databases do not scale as the system of record.”For some billion-edge workloads, graph OLTP can be difficult.Graph is projection/reasoning index. Authoritative writes live in event log + contract store.
“Event sourcing conflicts with right to erasure.”Raw PII in immutable logs is unacceptable.SAS tokenization + crypto-shredding; log stores encrypted/tokenized payloads only.
“AI will hallucinate merges.”Yes, if AI writes to truth directly.AI writes suggestions only; portals decide; Digital Jury/human gate for high risk.
“RYOW gateway will melt under load.”Thread-per-request implementation would fail.Non-blocking gateway, bounded wait, HTTP/2, backpressure, separate ingestion vs interactive gates.
“A universal person is philosophically nice but operationally vague.”Pure entity without handles is useless.Identity handles and evidence artifacts are first-class resources linked to pure entity.
“Consent and ABAC will sprawl.”They often do when every app implements its own logic.External CMP + OPA shell; RealMDM standardizes policy context and decision logs.
“Migration will be impossible.”Big bang would fail.Shadow registry, crosswalks, portalize new writes, projections, then cutover domain-by-domain.
Final position: RealMDM is not “anti-conventional MDM.” It is the next layer above it: a doctrine-backed, engineering-gated identity and meaning control plane that uses modern computation, graph reasoning, event history, AI stewardship, policy-as-code and privacy engineering to solve the tradeoffs older systems had to accept.

go
func (s *SensitiveAccessService) Reveal(ctx context.Context, req *pb.RevealRequest) (*pb.RevealResponse, error) {
    // 1. Workload identity. Only authenticated services call SAS.
    principal, err := s.authn.RequireSPIFFE(ctx, req.RequestorServiceId)
    if err != nil { return nil, status.Error(codes.Unauthenticated, "missing workload identity") }

    // 2. Vault lookup. Token is opaque; never infer data from token format.
    meta, err := s.vault.Lookup(ctx, req.TenantId, req.Token)
    if errors.Is(err, ErrNotFound) { return nil, Deny("VAULT_MISS") }

    // 3. Policy and consent decision before crypto.
    pdp, err := s.policy.CheckReveal(ctx, RevealPolicyInput{
        Principal: principal,
        Purpose: req.Purpose,
        TenantID: req.TenantId,
        DataType: meta.DataType,
        OwnerEntityID: meta.OwnerEntityID,
        ConsentDecisionRef: req.ConsentDecisionRef,
        Context: req.AbacContext,
    })
    s.audit.RecordAttempt(ctx, req, pdp)
    if err != nil || !pdp.Allow { return nil, Deny("DENY_POLICY_OR_CONSENT") }

    // 4. Revocation truth table: reachable KMS revoked always overrides cache.
    keyStatus, reachable := s.kms.Status(ctx, meta.KeyID)
    if reachable && (keyStatus == Disabled || keyStatus == Deleted || keyStatus == PendingDeletion) {
        s.cache.Flush(meta.KeyID)
        return nil, Deny("KEY_REVOKED")
    }
    if !reachable && !s.cache.Has(meta.KeyID) {
        return nil, status.Error(codes.Unavailable, "KMS_DOWN_FAIL_CLOSED")
    }

    // 5. Decrypt using cached or KMS-unwrapped DEK. Plaintext is never cached.
    dek, err := s.keyCache.GetOrLoad(ctx, meta.KeyID, meta.EncryptedDEK)
    if err != nil { return nil, status.Error(codes.Unavailable, "KEY_UNAVAILABLE") }
    plaintext, err := s.crypto.Decrypt(dek, meta.Ciphertext, meta.AAD())
    if err != nil { return nil, status.Error(codes.PermissionDenied, "DECRYPT_FAILED") }

    // 6. Obligations applied before returning.
    plaintext = ApplyObligations(plaintext, pdp.Obligations)
    s.audit.RecordReveal(ctx, req, meta, pdp)
    return &pb.RevealResponse{Plaintext: plaintext, Obligations: pdp.Obligations}, nil
}

Projection consumer near-code

go
func (w *ProjectionWorker) HandleEvent(ctx context.Context, ev cloudevents.Event) error {
    // Idempotency: projection consumers are at-least-once; writes must be idempotent.
    if w.seen.AlreadyProcessed(ctx, ev.ID()) { return nil }

    switch ev.Type() {
    case "realmdm.relationship.contract.verified.v1":
        var data ContractVerified
        if err := ev.DataAs(&data); err != nil { return err }

        // Graph projection: creates edge or reified node.
        if err := w.graph.UpsertRelationshipContract(ctx, data); err != nil { return err }

        // Domain read model: HR projection receives only HR-safe fields.
        if data.Domain == "HR" {
            if err := w.hrProjection.UpsertEmployeeView(ctx, data); err != nil { return err }
        }

        // OpenLineage emission for traceability.
        w.lineage.Emit(ctx, LineageEventFromCloudEvent(ev, "projection-worker"))

    case "realmdm.secure.sas.key.revoked.v1":
        var data KeyRevoked
        if err := ev.DataAs(&data); err != nil { return err }
        w.cache.InvalidateKey(data.KeyID)
    }

    return w.seen.MarkProcessed(ctx, ev.ID())
}
