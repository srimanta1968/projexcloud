P2 — Identity & Access at Scale

Tenant + extended hierarchy (Reseller · sub-tenant · BU recursion · GeographicNode · RoleTemplate · FiscalPeriod), six-layer JWT identity, consent receipts, ABAC + IQL, ReBAC with safeguards, end-customer API keys, and the Identity Projection System that closes G4.

Anchor docs: Architecture §7 · §11 · AIM-Identity-Model-v3.1

1 · Overview

P2 turns the substrate from P1 into a multi-tenant identity system. The data model centers on the six-layer identity tuple (Master Person · App Identity · Tenant Membership · Persona · [Encounter · Relationship]) and the Identity Projection that turns the runtime graph walk into a Redis-backed sub-millisecond read.

Extended hierarchy
Reseller · sub-tenant · BU · Geo
First-class Reseller (commission · white-label); recursive parent_tenant_id + parent_bu_id; GeographicNode tree (Region→Country→State→City→Locality); RoleTemplate inheritance; FiscalPeriod per tenant.
G4 closer
Identity Projection
Materialized subject_view per (person, app, tenant) in Redis (hot) + Postgres (durable). p99 ≤ 0.5ms warm. Refresh ≤ 1s after any membership/relationship/consent/policy event.
Access mesh
ABAC · ReBAC · Grants
ABAC + IQL DSL · ReBAC with ReBACTraversalBudget safeguards (depth cap 4) · Encounter Grants (P5). All decisions log to audit.
