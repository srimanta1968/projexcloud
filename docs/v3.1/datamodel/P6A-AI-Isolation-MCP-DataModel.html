P6A — AI Infrastructure · Agent Isolation · MCP Bridge

AI Gateway (multi-provider), Taxonomy (schemas + prompts), Agent Runtime with the four isolation primitives (capability tokens · execution TTL · deterministic replay · sandboxed memory), sdk-trace cross-system viewer (G12), and the bidirectional Model Context Protocol bridge.
Phase: P6A (Weeks 35–40)
Maps to wave: W6 first half
Gates closed: G7 (Agent Isolation Runtime) · G12 (sdk-trace)
PRD: prd/P6A-AI-Isolation-MCP.md
Anchor docs: Architecture §18A · AgenticIntegration §2 · §4

1 · Overview

G7 closer
Four isolation primitives
Capability tokens (signed, scope-limited, single-use) · Execution TTL (hard deadlines) · Deterministic replay (content-addressed execution log) · Sandboxed memory (hard physical partitions per tenant).
G12 closer
sdk-trace cross-system view
One trace_id resolves into a unified timeline crossing identity + consent + routing + Vault + policy + meter + SDK body + tool calls + lineage. Renders <5s after request completion.
Strategic primitive
sdk-mcp-bridge (consume + expose)
Register external MCP servers (Slack · Snowflake · Salesforce · GitHub · …) and expose selected ProjexCloud SDKs as MCP servers (callable from Claude Desktop, custom OpenAI assistants).
Why isolation MUST close before P6B. P6B introduces Conversation, Knowledge-RAG, Recommendation — all consume the agent runtime. One Phase-6B agent using a non-isolated runtime leaks Tenant A's prompt context into Tenant B's. The leak is catastrophic and irreversible. Hence G7 is a hard exit gate.
