Tenant Developer — Onboarding Guide

Discover SDKs, compose a build, and deploy your application on the ProjexCloud backbone.

Part of the onboarding suite. See onboarding-overview for the three-portal model and the identity model. Persona guides: Tenant Admin, Tenant Developer, App User, Platform Admin, ProjexCloud Admin.

Who you are & where you sign in

You build and operate applications for a tenant. You sign in at /workspace (port 3300) with your ProjexCloud identity; your tenant membership carries a developer/builder role. It is the same login you would use for Tenant Admin — only the role differs.

The build flow

  1. Open Workspace and browse the SDK registry (96 SDKs / 256 APIs) — search by intent ("metering", "evidence capture", "fleet dispatch").
  2. Compose a build plan: pick the SDK families your app needs; the planner wires identity, tenancy, metering, and audit for you.
  3. Implement domain logic — in Workspace or via the CLI with your coding agent connected through the MCP bridge.
  4. Validate against blueprints, tests and certification gates, then deploy.
  5. Operate: watch usage on the meter, traces, and diagnostics; iterate.

Working with multiple developers (and multiple apps)

  • Many developers collaborate inside the same app/tenant; ReBAC (sdk-rebac) and ABAC policy (sdk-policy) bound what each person can touch.
  • Identities are shared at the person level but isolated per app at L2/L3 — work on one app does not leak into another.
  • Each app has its own data model and event namespace (app_id); register a new App (via Platform Admin/onboarding) for each distinct product.
  • Use Business Units and feature flags (sdk-feature-flags) to stage rollouts and keep a kill-switch.

Never store identity as strings

The non-negotiable. No domain table stores a person’s name, address, device, or org as a primary string. Reference the canonical ID and the right identity layer (persona_id and above); fetch the name through the Persona/Profile SDKs with the access mesh on every call. A PR that adds a person_name column fails review.

Robotics developers — starter stack

For physical-AI / fleet apps, compose: sdk-device + hdk-camera (enroll & attest robots), sdk-ingest (telemetry), sdk-meter (per-robot metering), sdk-geo/sdk-dispatch/sdk-assignment (locate & task), sdk-evidence (capture), sdk-analytics/sdk-diagnostic-telemetry (fleet health), sdk-audit/sdk-approval (governance), sdk-ai-gateway/sdk-agent-runtime (autonomy), sdk-pool-router (scale). See the overview’s robotics example for sample data shapes.
