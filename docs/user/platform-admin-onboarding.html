Platform Admin (Operator) — Onboarding Guide

Operate ProjexCloud across all tenants: provisioning, capacity, billing ops, audit and compliance.

Part of the onboarding suite. See onboarding-overview for the three-portal model and the identity model. Persona guides: Tenant Admin, Tenant Developer, App User, Platform Admin, ProjexCloud Admin.

Who you are & where you sign in

You are a ProjexCloud operator — SRE, support, finance, or compliance. You sign in at /console (port 3100). This is a platform-level identity, distinct from any tenant identity: a tenant user cannot sign into the console, and you act across every tenant.

Provisioning a tenant

  1. Ensure the parent App exists (registered by ProjexCloud Admin). Create it first if none.
  2. Open Tenants → New, enter App ID, display name (company), region and isolation tier (S/P/G), optional brand domain.
  3. Submit — this writes tenant.tenant, emits tenant.created.v1 + tenant.pool.assigned.v1 through the audit chain, and assigns pool placement.
  4. Hand the tenant to the customer; their first user becomes tenant admin.

Authentication & the current gap

Read this before exposing the console. Privileged provisioning actions are gated by an ADMIN_OPS_TOKEN at the gateway, but the console UI itself currently has no enforced login gate. Until the portal auth middleware ships, restrict /console at the network edge (IP allow-list) so the server-held ops token is never reachable by an anonymous visitor. The Projexlight *Portal authentication middleware* feature tracks the fix.

Troubleshooting

  • Provision fails — verify the App ID exists and the ops token is configured.
  • Tenant lifecycle action blocked — some actions need a tenant-scoped JWT in addition to the ops token.
  • Pool hot — add a pool and migrate tenants offline (staged dual-write → atomic cutover).
